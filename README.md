# seabattle

Сетевой «Морской бой» на двоих. Сервер на C++20, клиент в браузере: создаёте комнату, отправляете
сопернику ссылку или код из 4 символов, расставляете флот и играете. Работает в локальной сети без
интернета, с телефона тоже.

Правила классические: поле 10×10, флот 1×4, 2×3, 3×2, 4×1, корабли не касаются даже углами. Попал -
стреляешь ещё, промахнулся - ход переходит. Вокруг потопленного корабля клетки отмечаются сами.
Сервер хранит оба поля и проверяет каждый ход: клиенту не уходят корабли противника, пока партия не
кончилась, так что подсмотреть через инструменты браузера не получится.

## Установка

Пакет для Debian 12 и 13 со страницы релизов:

```sh
sudo apt install ./seabattle_*-debian13.deb
```

Служба `seabattle` запускается сразу, игра на `http://адрес:8090/`. Адрес и порт меняются в
`/etc/default/seabattle`, затем `sudo systemctl restart seabattle`.

Docker:

```sh
docker compose up -d        # docker-compose.yml из репозитория
# или
docker run -d -p 8090:8090 ghcr.io/khromenokroman/seabattle:latest
```

Снаружи локальной сети ставьте сервер за обратный прокси с HTTPS (nginx, Caddy). Для nginx у
`/api/events` нужно отключить буферизацию (`proxy_buffering off;`), сервер дополнительно шлёт
`X-Accel-Buffering: no`.

## Запуск из исходников

Зависимости: компилятор C++20 (GCC 12+), CMake 3.25+, `nlohmann-json3-dev`, для тестов
`libgtest-dev` и `python3`. cpp-httplib лежит в `third_party/`.

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j"$(nproc)"
ctest --test-dir build --output-on-failure
./build/seabattle --web web --port 8090
```

Параметры: `--host` (по умолчанию `0.0.0.0`), `--port` (8090), `--web` (каталог клиента), `--version`, `--help`.

## Устройство

| Каталог | Что внутри |
|---|---|
| `core/` | игровая логика без сети: флот и правила расстановки, поле, партия |
| `server/` | комнаты, HTTP API, поток событий SSE, запуск |
| `web/` | клиент на HTML/CSS/JS без сборки и внешних библиотек |
| `docs/protocol.md` | протокол клиента и сервера |
| `tests/` | gtest для core и сервера, сквозная партия по HTTP, проверка клиента в headless Chrome, проверка deb и Docker |

Клиент отправляет действия обычными `POST` с JSON, а сервер присылает полный снимок состояния через
Server-Sent Events после каждого изменения. Клиент только рисует снимок, поэтому после перезагрузки
страницы или обрыва связи игра продолжается с того же места: токен игрока хранится в `localStorage`.

Комнаты живут в памяти процесса и удаляются через 30 минут, если ни один игрок не в сети. Каждый
открытый поток событий занимает поток сервера, их 128: это около 60 одновременных партий.
